# KRX 2026-10-29 WSL 중단·재시작 시 파일럿 마감 복구 (2026-10-28)

## 실제 발견한 문제
기존 KRX-J 호가·거래소 체결 틱·1분봉 수집은 2026-10-29 (목) 09:43 / 12:35 / 14:35 KST, 마감 독립 감사 및 동적 비용 비교는 15:45 KST에 WSL의 사용자 cron으로 실행되도록 등록했다.

그러나 WSL이 **15:45에 중단돼 있다면** 해당 시점의 마감 감사와 사용자 crontab 제거가 영원히 실행되지 않을 수 있다. 원래 정리는 오직 정확한 2026-10-29 날짜에만 허용돼 늦은 WSL 재개 시 사용자가 수동으로 정리해야 했다. 매년 10월 29일 같은 cron 표기가 남는 문제는 기존 거래일 프리플라이트가 주문·호가 API 실행을 거절하더라도 불필요한 오류와 위험을 만든다.

## 수정 사항
- 2026-10-29 **15:45 KST 원래 마감 시각**을 유지한다.
- 정규장 추가 시세 조회 없는 **시간당 한 번의 로컬 검사 예약**(`0 * * * *`)을 추가한다. 이 작업은 2026-10-29 15:45 이전에는 아무 것도 하지 않고, WSL/cron이 이후 살아 있는 첫 정시부터 잔여 마감 처리를 시도한다.
- 늦은 마감에서도 `quantlab.intraday_krx_joint_pilot_review`는 **2026-10-29 당일의 SHA 검증된 자료만 읽는다**. 수집이 누락된 오전·정오·오후 구간을 뒤늦게 KIS에서 조회해 동일 시간대 스냅샷처럼 저장하지 않는다.
- `final_review.json`에 `closeout_late_after_original_day` 및 `late_recovery_reads_only_original_market_data` 추가. 실제 마감 감사 시각과 요청된 거래일을 구분.
- 이미 작성된 불변 최종 보고서 또는 비용 비교 보고서는 **SHA/안전 불변 조건 확인만 수행**하며 덮어쓰지 않는다.
- 기존 동적 호가 비용 비교는 검증된 **2026-10-29 실제 원본**과 이전 **2026-10-28 KIS L2 응답**만 읽는다. KIS 주문·일봉/분봉 GET·인증 API 호출을 하지 않는다.
- `flock -n`으로 15:45 마감 프로세스와 매시간 복구 프로세스가 동시에 불변 보고서를 덮어쓰지 못하도록 한다.
- 2026-10-29 15:45 KST **이후라면 다른 날짜/해에도**, 정확히 지정된 파일럿 cron **헤더+5개 실행항목**만 삭제 가능하다. 그 외 cron 작업을 그대로 보존. 알려지지 않은 항목이 있거나 조작됐다면 fail closed.
- 파일럿은 일회성 연구로 유지한다. 파일럿 전체 3구간 수집 실패 시 최종 보고서의 `PARTIAL_OR_FAILED_RESEARCH_PILOT` 상태·빈 비용 결과를 성공으로 둔갑시키지 않는다. 관련 전략 수익률/체결률/종목 보유 수량은 미검증으로 유지한다.

## 실험·검증
- 2026-10-29 마감 전 현재 시각에 복구 감시 셸을 직접 실행하면 **네트워크·주문·실측 결과 생성 없이 종료**해야 한다.
- 별도 테스트에서 2026-10-30 06:00 KST에 WSL이 재개됐고 전날 수집 원본이 모두 없다는 경우: 최종 보고서는 `closeout_late_after_original_day=true`, `verified_windows=0`, `PARTIAL_OR_FAILED_RESEARCH_PILOT`로 기록한다.
- 2026-10-30 또는 2027-10-29에도 원래의 파일럿 cron 5개 + 헤더만 제거하는 테스트. 2026-10-29 15:45 이전에는 삭제 불가.
- 독립 회귀테스트 및 CI 완료 후에만 WSL 실제 crontab의 **15:45 실행 경로 교체, 시간당 복구 검사 한 건 추가**를 적용한다.
