# 청정 90일 전체 생애주기 — 합성 데이터 장기 회귀 검증 (2026-10-22)

## 검증의 목적

첫 유효일 6계좌·2호가가 정상인지만 검증하면 두 번째 날부터 90번째 날까지의 누적 회계·누락·재시도·종료 시점 오류를 놓칠 수 있다. 이 때문에 운영 원장이나 실제 Upbit 거래 데이터를 **일절 변경하지 않는 임시 SQLite**에서 사전등록 프로토콜의 90일 전체 경과를 오프라인으로 재생한다.

테스트: `tests/test_clean_90day_lifecycle.py` (CI 일반 테스트 및 Qlib 통합 테스트 모두 포함).

## 시나리오

1. **정상 90일**: `2026-10-22`~`2027-01-19 UTC`의 90개 대상 결정일을 매일 UTC 00:24에 합성 일봉과 공개 ticker *대역*으로 처리한다. 최종 6계좌 × 90일 = **540개 가상 이벤트**, BTC·ETH × 90일 = **180개 호가 증거**를 기대한다. 첫날·중간·마지막 누적 Watchdog가 PASS여야 한다.
2. **중복 방지**: 첫날·중간·마지막 동일 날짜를 00:34에 재실행하면 이벤트 추가 없이 `WAIT_NEW_BAR_OR_ALREADY_RECORDED`가 되어야 한다.
3. **영수증 유지**: 첫날 유효 감사 후 한 번 생성된 SHA 영수증은 90일 마지막 감사 시에도 동일 해시여야 하며 재발행하지 않는다.
4. **중간 하루 누락**: 두 번째 날의 가상관측을 건너뛰고 90번째 날까지 데이터를 기록하더라도 Watchdog는 `INCOMPLETE`, 누락 계좌·일 6건으로 판단해야 한다. 지나간 공개 ticker와 가상체결은 나중에 채우지 않는다.
5. **과거 호가 변조**: 90일 종료 직전 중간 날짜의 호가 원본을 임의 변경한 *합성 DB*는 누적 감사가 실패하며, 기존 첫날 승인 영수증을 덮어쓰지 않는다.
6. **평가 기간 후 추가 관측**: 91번째 날짜는 `OUTSIDE_PROTOCOL_WINDOW`로 처리하고 실제 계좌/증거 행 수를 변경하지 않는다.

## 해석·제한

이것은 실제 거래 체결·전략 성능·수익률·중개사 체결 품질을 입증하지 않는다. 매일 같은 합성 가격 경로를 사용하므로 실시간 Upbit 데이터의 소스 신뢰도·지연·시장 중단을 검증하는 테스트도 아니다.

**실제 첫날 검증 일정은 별개**: 2026-10-23 09:24 KST 수집, 10:50 KST 청정 Watchdog 및 첫날 SHA 봉인. 실제 6계좌·2개 호가 영수증이 확인되기 전에는 실관측 성공으로 보고하지 않는다. 실주문 및 자동 전략 승격은 비활성 상태를 유지한다.
